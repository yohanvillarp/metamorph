# Pull Request Templates & Contribution Standards

When an AI agent or human contributor prepares a Pull Request (PR) in Metamorph, **they must never use generic, unformatted PR descriptions**. Metamorph provides a suite of specialized, future-proof Pull Request templates located in [`.github/PULL_REQUEST_TEMPLATE/`](file:///c:/Users/yohan/myspace/lab/active/metamorph/.github/PULL_REQUEST_TEMPLATE) and the default [`.github/PULL_REQUEST_TEMPLATE.md`](file:///c:/Users/yohan/myspace/lab/active/metamorph/.github/PULL_REQUEST_TEMPLATE.md).

## 2. Invariants Enforced Across All Templates

Every PR description generated by an agent must verify and respect these core project invariants:

1. **Zero I/O in `@nikelyh/domain`**: Pure contracts, entities, and events. No `fs`, `node:sqlite`, `express`, or Mozaik SDK imports.
2. **Shadow Workspace Isolation**: All file mutations, scaffolding, and build verifications occur strictly inside `.metamorph/shadow/<runId>`. The user's original directory is never modified prior to `metamorph apply`.
3. **Mozaik v4 Event-Driven Bus**: Agents communicate exclusively through semantic events (`SemanticEventName`). No blocking synchronous execution loops (`await runLoop()`).
4. **Ephemeral Participant Lifecycle**: Temporary Worker and Reviewer participants must call `await participant.leave()` upon completion or timeout to prevent memory leaks.
5. **SQLite Auto-Migration Compatibility**: All database schema changes in `SQLiteStateStore.ts` must use safe, idempotent `ALTER TABLE` queries with try/catch to maintain backward compatibility with existing `.metamorph/history.db` files.
6. **Polymorphic Package Manager Compatibility**: Commands and scripts must adapt dynamically to the detected package manager (`pnpm`, `yarn`, `bun`, `npm`) without hardcoded assumptions.
7. **Strict Zero-Emoji Rule in Dashboard UI**: No emojis or unicode symbol characters in any UI component or label; use `lucide-react` vector icons exclusively.

## 3. Agent Protocol for PR Generation

When the user asks an agent to propose a Pull Request, branch name, or PR description:
1. **Identify the exact change category** from the table above.
2. **Read the corresponding template** from `.github/PULL_REQUEST_TEMPLATE/<template>.md`.
3. **Fill out all sections rigorously**, specifying root cause, architectural layers, verification evidence (`npm run typecheck`, `npm run test`, `npm run build`), and testing commands.
4. **Follow Conventional Commits**: Ensure the PR title follows `<type>(<scope>): <description>`.
